## 1. 事業の背景（ユーザーの言葉の要約）

- ユーザーは現在の仕事の引退後に「一人事業」を考えている。ハル はそのパートナー。
- 主軸は「人を集め、適切に情報を伝える」ことを仕組みとして徹底する事業。本人は「広告代理店」と仮に呼んでいるが、言葉は未定。
- 動機: 何かを作っても売れない、伝えられない、注目を集められない。耳目を集める人が正義の時代に、インフルエンサーになるのではなく、仕組みでそれをやりたい。
- ユーザーは「仕組みを作ること自体」が好きで、コンテンツは自分では決められない（決めたくない）。だから内容は反応に決めさせる設計にしてきた。
- ユーザーの明確な立場: 「半年やれば実績がつく」は NO。インターネットでは半年やっても誰も来ない可能性が高い。実績を掴むなら、絶対に成果を出せる場所を選ぶ。風見鶏は表向き（看板）である。
- 設計原理として採用した比喩: 大阪商人は日本海側の米を安く買って大阪で高く売った。「どの情報を、どこから仕入れ、誰に運ぶか」。情報の値段は境界（特に言語）をまたぐと変わる。仕入れ先の市場が既に投票済みの情報（Reddit 上位、Product Hunt 上位、Show HN 上位）を運べば、面白さを当てる必要がない。

## 3. 直近の議論で到達した方針（文書化はこれから）

### 3.1 立てる場所

「作れるけど届けられない人」が今週世に出したもの（個人開発者、同人作家、小さな店、自費出版の著者、インディーゲームの作り手）。理由: 将来の顧客がそこにいる、拾われる側が歓迎する、活動がそのまま事業の証拠になる、ユーザーの弱点（伝えられない）が他人の作品で何百回も実験できる研究テーマになる。

### 3.2 測るものの変更（提案、未実装）

- いまの腕は「ソース」。将来は「見せ方の型」（タイトル先行 / 画面添付 / 作者の一言引用 / 時間帯）を腕にする。
- 報酬は「いいね」から「作り手のところへ人が渡った数」（リンククリック、フォロー、GitHub の ★ の増分）へ寄せる。いいねはインフルエンサーの通貨で、追うと装置が扇情的な方へ漂流する。
- GitHub ソースは、現状「7 日以内 かつ ★50 以上」で既に届いたものを拾っている。「届いていないものへの介入」に変えるなら、「7 日以内、★3〜30、個人アカウント、README と説明あり、fork でない」に絞り、紹介前後の ★ の増分を記録する。

### 3.3 二つの航路（情報の裁定取引）

| | 航路A: 英語圏 → 日本語圏 | 航路B: 日本 → 英語圏 |
|---|---|---|
| 仕入れ | Product Hunt 上位、Reddit r/SideProject 等、Show HN、GitHub trending | 日本の個人開発・同人・インディーの発表（Bluesky、GitHub、BOOTH、itch.io） |
| 売り先 | 日本語 Bluesky、X、note、YouTube | Reddit の該当サブ、Product Hunt（ハンター制度）、Show HN、英語 Bluesky |
| 誰が得か | 日本の読者。作り手は外国人で、あなたを必要としない | 日本の作り手。英語と各プラットフォームの作法の壁を越えられない人 |
| 競合 | X に多数、Bluesky は薄い | ほぼ無人 |
| 自動化 | ほぼ全部可 | 発見・選別・英語の荷造り・測定は自動。投稿は人（Reddit は bot を嫌う） |
| 実績の形 | フォロワー、閲覧 | 作り手の作品についた外国からの ★・upvote・売上。作り手本人が目撃する |

ハル の推奨: 航路A は店の客寄せ（風見鶏のソースを「既に値のついた情報」に絞り替える）、航路B が商売そのもの。他人の作品を運ぶには本人の許可が要り、その一言が将来の顧客との最初の接点になる。

### 3.4 提案した最初の一歩

航路B を手作業で 10 件。日本の個人開発の発表を選び、許可を取り、Reddit の適切なサブか Product Hunt に英語で出し、前後の ★ と反響を記録する。2 週間で「運ぶと何が起きるか」が分かる。それが出たら発見と荷造りを自動化して風見鶏の裏側に据える。

## 5. 守ること（ガードレール）

- 一度に変える改善は一つ。効果は次の実測で判断し、予測で断定しない。
- 投稿頻度と探索日数は設定で固定し、数字を追って増やさない。
- 投稿文にデータに無い言葉を足さない。出典を必ず貼る。
- 過去のログを書き換えない。秘密情報を出力・コミットしない。
- 医療・金融・法律・政治・災害の指示に関わる内容は、ブログや動画に上げない。
- 他人の作品を運ぶときは本人の許可を取る。宣伝だけ、詐欺めいたもの、成人向けは拾わない。
- ユーザーの役割は「承認者」ではなく「編集長」。週 1 回レポートを読み、ソースの出し入れを決める。日々の数字には手を出さない。
