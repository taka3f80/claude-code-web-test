# 事業方針（正典）

最終更新: 2026-09-12 / 版: v0.4（棚の条件から日本語 UI を外した）

この文書は「なぜやるのか、どこに立つか、何を拾い何を拾わないか、何を測るか」の正典。
日々の状態や次の一手は `docs/HANDOFF.md`。捨てた案は `docs/decided-not-to-do.md`。ここには方針だけを書く。方針を変えたらここを直す。

## 0. 一行で

海外の良い IT サブスクを、日本の暮らしに「ととのう」形で届ける。継続報酬を商品棚に並べ、bot・SNS・サイト・動画のチャネルを AI で最適化して、実際に契約してもらう研究をする。研究の結果が売上になる。

## 1. なぜやるのか

- 一度契約すると課金が続くもの（携帯回線、クレジットカード、サブスク）が、商売として最強。そのおこぼれ、つまり月額利用料の一定割合が契約が続く限り入る「継続報酬」を取りに行く。
- 売り切りの成果報酬は追わない。1 件の契約が資産になる形だけを扱う。
- タカさんの強みは「仕組みを作ること」。弱みは「内容を決めること」「伝えること」。だから、何を見せるかは反応に決めさせ、伝え方の研究は装置に何百回もやらせる。
- 「半年続ければ実績がつく」は採らない。契約が計測できる場所に立ち、契約という数字で成否を判断する。

## 1.5 前提（タカさんの仕事の作り方）

project-haru の codex（`../project-haru/docs/codex-01.md`、`codex-02.md`）に抽出済み。この事業もその延長にある。

- **遊び → 整理 → 既存の場で試す → 波紋。** ゼロから場を立ち上げない。既にある場（Bluesky、YouTube、各社のアフィリエイト網）に遊びを持ち込み、反応が出たところを仕事にする。
- **仕掛け志向。** 「AI で効率化」はつまらない。試したいのは「AI が前提の世界で、集客と成約を装置がやったら何が起きるか」。継続報酬の棚は、その仕掛けを金額で測るための計器。
- **完全自走を目指す。** タカさんは介入権だけ持つ観察者になるのが目標。だから最初から「人が毎日やる作業」を設計に入れない。人がやるのは登録・契約・週次の判断だけ。
- **いいね数で測らない。** 深い滞在、再訪、契約で測る。記事の量と質で勝負するモデルからは降りる。
- **のんびり＝自律。** 他人に指図されない状態を守る。ネットワークの規約や広告主の要求に振り回される棚は載せない。
- **なんちゃって翻訳者。** 英語圏の道具と日本の暮らしの間に立ち、両方の言葉を片言で話す。それがこの事業の立ち位置そのもの。

## 2. どこに立つか

### 2.1 対象は日本（2026-09-12 決定）

- 読者は日本語話者。海外の IT サービスを使うことに日本人が感じる壁（英語、USD 課金、作法）を、こちら側で手を引いて越えさせる。
- 理由: 裁定取引が成立するのは日本向けだけ。英語圏では同じ道具の紹介が飽和していて値差が無い。判定役のタカさんが日本語読者の反応を肌で読める。風見鶏が既に日本語で走っている。
- 海外向けは、この装置の言語を差し替えた 2 台目。日本で「クリックが契約になる率」を測ってから立てる。逆の順は切り分けができない。
- 引き受ける弱点: 市場が小さい。日本の読者が英語 UI と USD 課金の道具を契約するかが最大の未知数。ただしその壁こそが商品で、壁を越える手引きが価値を生む。日本語 UI の有無は棚の条件にしない（2026-09-12、タカさん）。

### 2.2 商品棚

- 棚に並べるのは「継続報酬型」のプログラムだけ。月額の X% が N か月または無期限に入るもの。
- 日本の ASP には継続報酬型がほぼ無い。2026-09-12 の調査で確認済み（`docs/research/2026-09-12-affiliate-shelf.md`）。主戦場は海外 SaaS の直営プログラムと PartnerStack / Impact。
- 棚に載せる条件:
  1. 公式ページで報酬条件が確認できる
  2. 継続報酬である（renewal に報酬が出る）
  3. 日本在住の個人が参加でき、円または PayPal 等で受け取れる
  4. 自分が実際に触って説明できる、または触る予定がある
  5. 日本語が無くても「あまりに良い」と思えるもの。日本語 UI があるものは誰でも運べて値差が薄い。無いのに良いものは、申込みと使い方を日本語で手引きすること自体が価値になる
- 調査で見えた棚の形（案、未決）:
  - 候補は「サービスの良さ × 継続報酬の厚さ × 日本での知られていなさ」で並べる。調査は `docs/research/` に追記していく。IT に関係ない普通の人が使うもの（VPN、パスワード管理、保存、翻訳、学習、健康、家計）を優先して探す。
  - ネットワークはまず PartnerStack 一つ。日本が明記され、PayPal / Stripe なら税務書類が要らない。

### 2.3 名前と顔

- 名前は **Sopiva**（ソピバ、フィンランド語で「ちょうどいい、しっくりくる」。2026-09-12 決定）。根は「ととのう」。海外にありそうな名前を掲げ、その日本語版として見せる。日本人の海外サービスへの警戒を、看板で解く。
- 海外の会社だと名乗らない。運営者は MaiWay または川崎崇史で正直に出す。「グローバルな作りのサービスを日本から運営している」までが正しい範囲。
- 言語切替に English を最初から置く。後で本当に英語版を出せば、それが 2 台目になる。
- 見た目は北欧の静けさ。「ととのう」を設計で表す。

### 2.4 場所

- 湊（サイト）は **sopiva.project-haru.org** に、Astro + Cloudflare Workers で新しい repo として作る（2026-09-12 決定。ゼロ円で始める）。ドメインは本命ではない。当たったら独自ドメインへ 301 で引っ越す。
- project-haru 本体とは repo も Worker も分ける。憲章（AI 活用ブログではない、広告収益で測らない）を汚さない。読者（経営者）も違う。実験が動き出したら Story を 1 本書いて湊に渡す、それだけにする。
- SNS と動画から貼るリンクは必ず湊の URL（記事か /go/）にする。引っ越しのとき 301 で全部追える。
- sarudeki.com は使わない（2026-09-12、タカさん決定）。
- 風見鶏（Bluesky bot）はこの repo のまま。裏方の計器で、表のブランドではない。

## 3. 4 つのチャネルの役割

チャネルは物理が違う。「風を読む場所」と「積む場所」を分ける。

| チャネル | 物理 | 役割 | 測るもの |
|---|---|---|---|
| Bluesky 風見鶏 | フィードの波。安い、速い、全自動 | **風を読む**。どの話題・どの見せ方に日本語読者が反応するかを毎日測る。勝った話題を記事と動画の題材に回す。PR 付きで湊の記事も流す | 反応、湊への渡り |
| 湊（Astro + Cloudflare） | 検索で積み上がる。月単位で残る | **積む、契約が起きる**。棚と記事が置かれる唯一の場所。全チャネルのリンクはここに集まる | 棚リンクのクリック、契約 |
| YouTube | 第二の検索エンジン。題名は Google の検索結果を見据えて書く | **積む**。英語しか説明の無いツールの、日本語の「始め方・料金・比較」を短い動画で置く。説明欄から湊へ。MOSTLY TRUE JAPAN LAB とは別チャンネル | 検索流入、説明欄クリック |
| TikTok | 検索ゼロ、波は 3 日で収束 | **呼び込みの実験枠**。同じ動画を再掲するだけ。4 週間で湊へ人が渡らなければ落とす | 湊へのクリックだけ |

video-lab で学んだ物理をそのまま使う: YouTube は検索だけが積み上がる、フィードの波は 1〜2 日で消える、TikTok は検索がほぼゼロ、制作は型にはめる、差がつくのは調査。

```
 風見鶏 ──(勝った話題)──▶ 記事・動画の題材
    │                          │
    └──(PR付き投稿)──▶ 湊 ◀──(説明欄)── YouTube / TikTok
                       │
              /go/ 計測リンク（SubID 付き）
                       │
                 各社の申込ページ ──▶ 契約 ──▶ 継続報酬
```

- bot や動画からアフィリエイトリンクへ直接飛ばさない。必ず湊を経由する。理由: PR 表記を湊で確実に出せる、計測を一箇所に集められる、bot のプロフィール「人は書いていません」との整合が取れる。
- 湊の要は `/go/<棚>?s=<チャネル>.<投稿ID>` の転送 Worker。クリックを D1 に記録し、週次で PartnerStack の成果と SubID で突き合わせる。これが「どのチャネルのどの見せ方が契約を生んだか」を知る唯一の帳簿。

## 4. 作る順番（一段ごとに数字が出る）

0. 棚の 1 本目を決め、PartnerStack に登録する。タカさんの手。名前は Sopiva、場所は sopiva.project-haru.org で決定済み。
1. **湊の骨組み**。maiway / project-haru の Astro 雛形を写して新 repo。/go/ Worker と D1 の帳簿、棚ページ 1 枚に PR 表記、運営者表記。出る数字: クリック数。
2. **記事 3 本**。棚 1 本目の「料金」「始め方」「比較」。Search Console 登録。出る数字: 検索表示と流入。遅い指標なので早く撒く。
3. **風見鶏を湊につなぐ**。腕に「湊の記事」を足し、報酬をいいねから「湊へのクリック」に替える。変更はこの一つだけ。出る数字: 投稿の型ごとの渡り率。
4. **動画 1 本**。video-lab の型で日本語チュートリアルの短尺を 1 本。YouTube を先、TikTok は再掲。出る数字: 検索流入と説明欄クリック。
5. **週次レポートを漏斗の形に**。チャネル × SubID のクリック、契約、報酬額を一枚に。編集長が読んで棚と題材を出し入れする。

## 5. 何を拾い、何を拾わないか

### 拾う

- 継続報酬型で、条件を公式に確認できたプログラム
- 日本語が無くても良すぎるもの。手引きが価値になる
- 自分の読者が実際に使いそうなもの。読者の反応（クリック、滞在、契約）が裏付けるもの
- 「既に値のついた情報」。仕入れ先の市場で票が入ったもの（HN 上位、Product Hunt 上位、GitHub の伸び）を運ぶ。面白さを当てに行かない

### 拾わない

- 売り切りの成果報酬だけのもの
- 医療・金融商品・法律・政治・災害の指示に関わるもの（クレジットカードは「最強」だが、金融商品の勧誘は法規制と読者の信頼の両面で扱わない。通信回線は日本の ASP 中心で継続報酬でないため当面外す）
- 成人向け、詐欺めいたもの、宣伝だけのもの
- 自分が説明できないもの

## 6. 何を測るか

### 6.1 漏斗の各段

| 段 | 指標 | 取り方 |
|---|---|---|
| 注目 | 投稿の反応、動画の再生 | Bluesky API（風見鶏が取得済み）、YouTube Studio |
| 渡り | 湊へのクリック、記事の閲覧 | /go/ の帳簿と Cloudflare Web Analytics |
| 棚 | 棚リンクのクリック | /go/ の帳簿。SubID で投稿・型・チャネルを識別 |
| 契約 | 成約数、継続月数、報酬額 | PartnerStack の管理画面。SubID で突き合わせ |

### 6.2 装置の報酬

- 今の風見鶏の報酬は「いいね等 ≥ 1」。これは「注目」の段しか見ていない。
- 目標は「契約」だが、契約は月に数件しか起きず、学習には薄い。そこで二段にする:
  - 日々の学習: 「渡り」と「棚」のクリック（頻度が高く、契約と相関する見込み）
  - 週次の判断: 「契約」と報酬額。編集長がレポートを読んで棚とソースを出し入れする
- いいねを目的にしない。いいねはインフルエンサーの通貨で、追うと装置が扇情的な方へ漂流する。

### 6.3 腕（何を競わせるか）

- 現行: ソース（どこから拾うか）
- 追加予定: 見せ方の型（タイトル先行 / 画面添付 / 一言引用 / 時間帯）と、棚の並べ方（どの記事にどの棚を添えるか）
- 一度に変える改善は一つ。効果は次の実測で判断し、予測で断定しない。

## 7. 自動化の順番

「人が毎日触るものを順に消す」順番で進める。

1. 風見鶏の投稿と計測: 済み（GitHub Actions）
2. 記事の生成: 週次の Actions + Claude API。出典と自動生成を明記。最初はタカさんが目視、慣れたら自動
3. 動画の描画と YouTube 投稿: Remotion は Actions で回せる。YouTube Data API の OAuth はタカさんが一度だけ通す
4. TikTok: API 審査の壁があるので手動のまま。伸びなければ落とす
5. 週次レポート: /go/ の帳簿と PartnerStack の成果を SubID で結合して一枚に

人に残る仕事は、登録・契約・OAuth・週 1 回の判断だけ。

## 8. ガードレール

- アフィリエイトリンクを含む投稿・ページには「PR」「広告」を明示する（景品表示法のステマ規制、2023 年 10 月施行）。
- bot が書いていることをプロフィールとサイトに明記する。
- 投稿文にデータに無い言葉を足さない。出典を必ず貼る。
- 投稿頻度と探索日数は設定で固定し、数字を追って増やさない。
- 過去のログを書き換えない。秘密情報（ASP のトークン、アプリパスワード）はコードにも会話にも書かない。
- アカウント作成、契約、決済、ドメイン登録、OAuth に関わる操作は人がやる。ハル は代行しない。
- 他人の作品を運ぶときは本人の許可を取る。

## 9. 役割

- タカさん: 編集長。週 1 回レポートを読み、棚とソースの出し入れを決める。ASP・ネットワーク・ドメイン・各チャネルのアカウントはタカさんが持つ。
- ハル: 装置の設計・実装・計測・レポート。調べ物は Sonnet / Opus のエージェントに振る。方針を変えたらこの文書と HANDOFF.md を更新する。

- 海外向けの 2 台目: 日本で「クリックが契約になる率」が出てから。
