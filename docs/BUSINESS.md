# 事業方針（正典）

最終更新: 2026-09-12 / 版: v0.1（下書き。棚の中身は `docs/research/` の調査で埋める）

この文書は「なぜやるのか、どこに立つか、何を拾い何を拾わないか、何を測るか」の正典。
日々の状態や次の一手は `docs/HANDOFF.md`。ここには方針だけを書く。方針を変えたらここを直す。

## 0. 一行で

継続課金サービスの継続報酬を商品棚に並べ、bot・SNS・サイト・動画のチャネルを AI で最適化して、実際に契約してもらう研究をする。研究の結果が売上になる。

## 1. なぜやるのか

- 一度契約すると課金が続くもの（携帯回線、クレジットカード、サブスク）が、商売として最強。そのおこぼれ、つまり月額利用料の一定割合が契約が続く限り入る「継続報酬」を取りに行く。
- 売り切りの成果報酬は追わない。1 件の契約が資産になる形だけを扱う。
- タカさんの強みは「仕組みを作ること」。弱みは「内容を決めること」「伝えること」。だから、何を見せるかは反応に決めさせ、伝え方の研究は装置に何百回もやらせる。
- 「半年続ければ実績がつく」は採らない。契約が計測できる場所に立ち、契約という数字で成否を判断する。

## 1.5 前提（Web 版の引き継ぎから抜けていたもの）

タカさんの仕事の作り方は project-haru の codex（`../project-haru/docs/codex-01.md`、`codex-02.md`）に抽出済み。この事業もその延長にある。

- **遊び → 整理 → 既存の場で試す → 波紋。** ゼロから場を立ち上げない。既にある場（Bluesky、YouTube、各社のアフィリエイト網）に遊びを持ち込み、反応が出たところを仕事にする。
- **仕掛け志向。** 「AI で効率化」はつまらない。試したいのは「AI が前提の世界で、集客と成約を装置がやったら何が起きるか」。継続報酬の棚は、その仕掛けを金額で測るための計器。
- **完全自走を目指す。** タカさんは介入権だけ持つ観察者になるのが目標。だから最初から「人が毎日やる作業」を設計に入れない。人がやるのは登録・契約・週次の判断だけ。
- **いいね数で測らない。** 深い滞在、再訪、契約で測る。記事の量と質で勝負するモデルからは降りる。
- **のんびり＝自律。** 他人に指図されない状態を守る。ネットワークの規約や広告主の要求に振り回される棚は載せない。

## 2. どこに立つか

### 2.1 商品棚

- 棚に並べるのは「継続報酬型」のプログラムだけ。月額の X% が N か月または無期限に入るもの。
- 日本の ASP には継続報酬型がほぼ無い。2026-09-12 の調査で確認済み（`docs/research/2026-09-12-affiliate-shelf.md`）。主戦場は海外 SaaS の直営プログラムと PartnerStack / Impact。
- 調査で見えた棚の形（案、未決）:
  - 1 本目候補: Kit（12 か月 50%）、beehiiv（12 か月 50〜60%）、ElevenLabs（12 か月 22%、日本語 UI）。風見鶏の読者に近い。
  - 2 本目候補: systeme.io（無期限 60%）、Thinkific（無期限 30%）。読者が「作る側」に回ったときの受け皿。
  - 保険: NordVPN（更新 30%、日本語 UI）。読者層を選ばない。
  - ネットワークはまず PartnerStack 一つ。日本が明記され、PayPal / Stripe なら税務書類が要らない。
- 棚に載せる条件:
  1. 公式ページで報酬条件が確認できる
  2. 継続報酬である（renewal に報酬が出る）
  3. 日本在住の個人が参加でき、円または PayPal 等で受け取れる
  4. 自分が実際に触って説明できる、または触る予定がある
  5. 読者が日本語で契約まで進める（日本語 UI か、少なくとも日本語の申込導線がある）

### 2.2 読者

- 一次: 風見鶏に集まる読者。AI・技術・新しいものに反応する日本語話者。
- 棚の分野は読者に合わせる。読者を棚に合わせない。風見鶏のソース構成が AI・技術寄りなので、最初の棚も AI・生産性・開発ツール寄りになる見込み。ただしこれも計測で決める。

### 2.3 私たちの役割

- 私たちはインフルエンサーではない。「どの棚を、どのチャネルで、どう見せると契約に至るか」を測って改善し続ける仕組み屋。
- 風見鶏は看板であり研究所。棚そのものではない。風見鶏が集めた注目を、サイトの棚に渡す。

## 3. 漏斗の構造

```
風見鶏（Bluesky bot）        注目を集める。反応で次のソースと見せ方を選ぶ
        ↓ 
サイト（GitHub Pages）        棚と記事。PR 表記。ここに計測付きのリンクを置く
        ↓
動画（YouTube Shorts）        記事のダイジェスト。説明欄からサイトへ
        ↓
プログラム側の申込ページ      契約。ASP/ネットワークの管理画面で成果を確認
```

- bot の投稿からアフィリエイトリンクへ直接飛ばさない。必ずサイトを経由する。理由: PR 表記をサイトで確実に出せる、計測を一箇所に集められる、bot のプロフィール「人は書いていません」との整合が取れる。
- 「作ってきたものを 1 本形にする」ので、風見鶏を捨てて別の bot を作るのではなく、風見鶏の後ろに棚をつなぐ。

## 4. 何を拾い、何を拾わないか

### 拾う

- 継続報酬型で、条件を公式に確認できたプログラム
- 自分の読者が実際に使いそうなもの。読者の反応（クリック、滞在、契約）が裏付けるもの
- 「既に値のついた情報」。仕入れ先の市場で票が入ったもの（HN 上位、Product Hunt 上位、GitHub の伸び）を運ぶ。面白さを当てに行かない

### 拾わない

- 売り切りの成果報酬だけのもの
- 医療・金融商品・法律・政治・災害の指示に関わるもの（クレジットカードや通信回線は「最強」だが、金融商品の勧誘は法規制と読者の信頼の両面で扱わない。通信回線は日本の ASP 中心で継続報酬でないため当面外す）
- 成人向け、詐欺めいたもの、宣伝だけのもの
- 自分が説明できないもの

## 5. 何を測るか

### 5.1 漏斗の各段

| 段 | 指標 | 取り方 |
|---|---|---|
| 注目 | 投稿の反応（いいね・リポスト・返信・引用） | Bluesky API。現行の風見鶏が取得済み |
| 渡り | サイトへのクリック、記事の閲覧 | サイト側の計測（実装は未定。Cloudflare Web Analytics 等） |
| 棚 | 棚リンクのクリック | 各ネットワークの SubID/clickref 付きリンクで投稿単位に識別 |
| 契約 | 成約数、継続月数、報酬額 | ネットワークの管理画面。SubID で投稿・型・チャネルに紐づける |

### 5.2 装置の報酬

- 今の風見鶏の報酬は「いいね等 ≥ 1」。これは「注目」の段しか見ていない。
- 目標は「契約」だが、契約は月に数件しか起きず、学習には薄い。そこで二段にする:
  - 日々の学習: 「渡り」と「棚」のクリック（頻度が高く、契約と相関する見込み）
  - 週次の判断: 「契約」と報酬額。編集長がレポートを読んで棚とソースを出し入れする
- いいねを目的にしない。いいねはインフルエンサーの通貨で、追うと装置が扇情的な方へ漂流する。

### 5.3 腕（何を競わせるか）

- 現行: ソース（どこから拾うか）
- 追加予定: 見せ方の型（タイトル先行 / 画面添付 / 一言引用 / 時間帯）と、棚の並べ方（どの記事にどの棚を添えるか）
- 一度に変える改善は一つ。効果は次の実測で判断し、予測で断定しない。

## 6. ガードレール

- アフィリエイトリンクを含む投稿・ページには「PR」「広告」を明示する（景品表示法のステマ規制、2023 年 10 月施行）。
- bot が書いていることをプロフィールとサイトに明記する。
- 投稿文にデータに無い言葉を足さない。出典を必ず貼る。
- 投稿頻度と探索日数は設定で固定し、数字を追って増やさない。
- 過去のログを書き換えない。秘密情報（ASP のトークン、アプリパスワード）はコードにも会話にも書かない。
- アカウント作成、契約、決済に関わる操作は人がやる。ハル は代行しない。
- 他人の作品を運ぶときは本人の許可を取る。

## 7. 役割

- タカさん: 編集長。週 1 回レポートを読み、棚とソースの出し入れを決める。ASP・ネットワークの登録と管理画面はタカさんが持つ。
- ハル: 装置の設計・実装・計測・レポート。方針を変えたらこの文書と HANDOFF.md を更新する。

## 8. 保留していること

- 航路B（日本の作り手の作品を英語圏へ運ぶ）: 継続報酬の入り口が無いので、棚で 1 本売上が立つまで保留。捨ててはいない。詳細は `docs/HANDOFF.md` 3.3。
- 事業の呼び名: 決めない。
- 通信回線・クレジットカード: 「最強」の典型だが、上記 4 の理由で当面扱わない。継続報酬型で扱える形が見つかれば再検討。
